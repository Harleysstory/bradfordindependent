Bot Privacy Policy

The short version: the bot is a relay, not a record keeper. It takes activity notifications from GitHub repositories that server administrators have asked it to watch and posts a summary message in a Discord channel. It stores almost nothing, reads no messages, and shares nothing with anyone else.

Last updated: November 2026. This policy covers the Bradford Independent Discord bot ("the bot", application ID 1567388231694164008), operated by Harley Bradford ("Bradford Independent", "we", "us"). For our website and consultancy generally, see the main privacy policy.

Who this policy is for

This policy applies to members of Discord servers that use the bot, and to people whose activity on GitHub appears in those servers. If you are a server administrator, you decide which repositories the bot watches and which channels it posts in; if you are a server member or a GitHub contributor, your data is handled as described below.

What the bot receives and posts

When a repository owner connects the bot to a GitHub repository, GitHub sends the bot a notification whenever something happens in that repository — for example a commit is pushed, a pull request or issue is opened, or a release is published. The bot then posts a summary message in the configured Discord channel. These messages may contain:

  • repository, branch and release names;
  • commit messages and short commit identifiers;
  • pull request, issue and review titles and descriptions;
  • GitHub usernames (handles) of the people who performed the action; and
  • links to the relevant pages on github.com.

This information comes from GitHub at the moment of the event. The bot does not browse repositories, does not read source code, and does not make any other requests to GitHub beyond receiving these notifications.

What the bot stores

To know where to post, the bot keeps a small configuration file on its host server containing, for each Discord server that uses it:

  • the Discord server ID and channel IDs chosen by its administrators;
  • the names of the repositories being watched;
  • which event types administrators have chosen to receive; and
  • optional links between a GitHub username and a Discord user ID, created only when an administrator chooses to link them, so that person can be notified of activity.

This configuration contains no message content, no personal conversations, and no information about you beyond the identifiers listed above. It can be inspected or deleted on request at any time (see Contact below). Removing the bot from a server, or an administrator running the bot's unwatch command, deletes the configuration for that server or repository.

What the bot does not do

  • It does not read or store any Discord messages — it has no "message content" access and only sends its own announcements.
  • It does not use analytics, advertising, or tracking of any kind.
  • It does not sell, share or transfer data to any third party.
  • It does not profile users or make automated decisions about anyone.

Where data lives

The bot's configuration file is stored on the server that hosts the bot, secured with modern encryption in transit, and never leaves that server except in the form of the messages it posts to Discord. Discord messages themselves are governed by Discord's terms and privacy policy. GitHub event data is governed by GitHub's privacy statement.

Legal basis and your rights

The bot processes this limited data on the basis of the legitimate interests of server administrators in receiving development activity notifications, at their request and under their control. Under UK data protection law (the UK GDPR and Data Protection Act 2018) you have the right to be told what data is held, to see a copy of it, to have it corrected or deleted, and to object to its use. Since the data held is minimal, these requests are quick to fulfil.

Data retention

Configuration for a server or repository is kept only while the bot remains connected to it, and is deleted when the bot is removed from the server or the repository is unwatched. Event notifications themselves are not archived — they are relayed to Discord within seconds and not retained by the bot.

Changes to this policy

If this policy changes, the "last updated" date at the top of this page will change too.
